# Aux Command distribution packaging

This directory holds the community-distribution packaging that reaches Linux
users beyond the GitHub release page: **Flatpak** (for Flathub) and **AUR**
(for Arch-family users). The canonical AppImage/`.deb`/`.rpm` artifacts are
still produced by `npm run dist:x64`; these wrap or rebuild those.

## Flatpak

`flatpak/tech.auxillo.command.yml` wraps the released x86_64 AppImage on top of
the `org.electronjs.Electron2.BaseApp`, so the sandbox ships the correct Electron
runtime without a Node build. It installs a desktop entry, AppStream metainfo,
and hicolor icons.

Per release:

1. Build and publish the AppImage (`npm run dist:x64`).
2. Note its SHA-256 (printed by `node scripts/release-manifest.cjs`, or
   `sha256sum Aux-Command-<version>-x86_64.AppImage`).
3. Update `url` and `sha256` in the manifest to the pinned release asset.

Local build and install:

```bash
flatpak install -y flathub org.freedesktop.Sdk//23.08 \
  org.freedesktop.Platform//23.08 org.electronjs.Electron2.BaseApp//23.08
flatpak-builder --user --install --force-clean build-dir \
  packaging/flatpak/tech.auxillo.command.yml
flatpak run tech.auxillo.command
```

Flathub submission: open a PR against `flathub/flathub` adding this manifest
(renamed to the app id) plus the `.desktop` and `.metainfo.xml`. The manifest
must reference a pinned, hash-verified release URL — never a moving `latest`.

Sandbox permissions are intentionally scoped: `~/.ssh` (config and identities),
`xdg-download` and `host` filesystem for transfers, `--device=all` for serial
consoles, and the Secret Service / KWallet names for the credential vault.

## AUR

Two packages under `aur/`:

- **`aux-command-bin`** — repackages the released AppImage. Fast to install,
  no build toolchain. Set `sha256sums` to the release AppImage hash.
- **`aux-command`** — builds from a tagged source checkout with
  `electron-builder` (`npm run pack`) and installs the unpacked tree.

Both declare `openssh` and `python` as hard dependencies and everything else
(FreeRDP, TigerVNC, Xvfb, x11vnc, Mosh, whois, bind) as `optdepends`, matching
the app's graceful-degradation model.

Publishing to the AUR:

```bash
cd packaging/aur/aux-command-bin      # or aux-command
# update pkgver and sha256sums for the release
makepkg -si                            # local test build/install
makepkg --printsrcinfo > .SRCINFO      # regenerate the AUR metadata
git clone ssh://aur@aur.archlinux.org/aux-command-bin.git aur-repo
cp PKGBUILD .SRCINFO aur-repo/
cd aur-repo && git commit -am "aux-command-bin ${pkgver}" && git push
```

`.SRCINFO` is generated by `makepkg --printsrcinfo` at publish time and is not
committed to this repository (it must match the exact `pkgver`/hashes of the
AUR push).

## Icons and desktop entry

The desktop entry (`flatpak/tech.auxillo.command.desktop`) and icons in
`build/icons/` are shared by both packaging paths and by the `.deb`/`.rpm`
builds, so branding stays identical across every distribution channel.
